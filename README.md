# VITALIS

Healthcare coordination for the ITDC 2026 hackathon (Chrisland University, Abeokuta). VITALIS gets a patient from
"something is wrong" to "a hospital that can handle this is ready for you" as fast as possible: tap-only triage,
deterministic red-flag rules, our disease model, live hospital matching, and referrals that hospitals accept or decline
in real time.

> **Synthetic data only.** Every facility, person and phone number in this repo is fictional. Clinical rules in
> `backend/data/*.json` are drafts marked `needs_clinical_review` and must be reviewed by clinicians before any real use.

## What works today (MVP, demo path first)

- **Patient app (no login):** 8 emergency buttons + "Something else", who-picker, original front/back body map with a
  zoomed head, symptom picture cards, 5 original "how bad" faces, onset, results. Device key in IndexedDB, VITALIS ID
  and one-time recovery code, restore on a new phone.
- **Triage engine:** red-flag rules → disease model (stub, 800 ms timeout, falls back to region defaults) → care type →
  matching, on every tap. Rules version and every model prediction are stored. Family never sees disease names.
- **Matching:** hard filter on essential services, score = 40 service + 25 availability + 20 distance + 15 freshness,
  reasons and exclusions returned, Confirmed / Stale / Unknown freshness labels, ETA estimate.
- **Referrals:** heads-up to the top 3 hospitals when a red flag fires, live SSE on both sides, decline (reason
  required) → next hospital offered automatically, accept → "Go now" with directions and what to bring, arrival
  confirmation, overdue job with SMS (console provider in dev).
- **Hospital screens:** live incoming queue, accept / decline / ready / arrived by role, one-tap service availability,
  and staff approvals for the facility admin.
- **Registration + verification:** facilities, hospital staff and frontline workers self-register (licence number +
  document, validated by magic bytes, 5 MB max, private storage). Network admin approves / rejects / suspends facilities
  and workers; facility admins approve their own staff. Rejected applicants resubmit. Status page for anyone not
  approved.
- **Frontline worker app (`/worker`):** chemists / CHEWs / midwives triage a walk-in "on behalf of patient" with the same
  tap flow, add vitals (BP, pulse, temperature, SpO₂, respiratory rate, weight) that re-run the red-flag rules
  immediately, refer, follow "My referrals" live (accepted / declined with reason / arrived / overdue, with SMS on
  overdue), and hand the family a printable recovery slip.
- **Receiving hospital:** arrival opens the encounter pre-filled from the referral; patient board by stage (live);
  nursing vitals beside the chemist's with trend arrows, urgent flags and corrections that keep the original; doctor
  notes (draft → sign → amend), lab/radiology orders; lab queue with result entry and separate verification;
  disposition and completion; full timeline with every handoff, time and staff name; walk-in registration.
- **Doctor AI (from the team's NCS repo):** VITALIS AI ranks possible conditions with cited evidence, raises red flags,
  shows trends, runs the **team's trained diabetes and heart models** (bands, measured vs assumed inputs), and screens
  treatments against allergies/medicines recorded at other hospitals. Safety-checked prescribing with audited override.
  Accept/edit/reject AI drafts; optional Gemini/Groq narrative with a canned fallback.
- **Network admin:** verification queue with documents, audit log viewer with filters, network counts (no patient names).
- **Platform:** Argon2 + JWT in httpOnly cookies, CSRF double-submit, role + facility scoping, audit events, rate limits,
  security headers, response envelope, structured logs with request IDs. PWA with Serwist and an offline page.

Not built yet (next phases): records + QR sharing, web push, full i18n text.

## Run it locally (no Docker needed)

Needs Python 3.12 via [uv](https://docs.astral.sh/uv/), Node 22, and PostgreSQL 16+ on `localhost:5432`.

```bash
make setup      # deps, local DBs (vitalis, vitalis_test), migrations, demo seed
make dev        # model :8100, backend :8000, frontend :3000
```

Open http://localhost:3000. Staff logins are in `backend/var/DEMO_LOGINS.md` (gitignored, regenerated by
`make demo-reset`). The demo script is in [docs/demo-script.md](docs/demo-script.md).

```bash
make test       # backend tests (auth, scoping, red flags, matching, referrals, overdue)
make lint       # ruff + eslint + tsc
make types      # regenerate frontend/types/api.ts from the FastAPI OpenAPI schema
```

## Layout

```
backend/   FastAPI modular monolith (app/core, models, schemas, api/v1, services, engines, realtime), Alembic, tests
  data/    symptoms.json (UI taxonomy + model_code mapping), red_flags.json, care_types.json, lgas.json
model/     disease-model STUB service (POST /predict). Our real model replaces it behind the same contract.
frontend/  Next.js 16 App Router PWA: (patient) flow, hospital/, auth/
deploy/    docker-compose.yml, nginx.conf, Dockerfiles, deploy.sh (one VPS)
docs/      architecture.md, api.md, demo-script.md
```

## Deploy (one VPS)

```bash
cp .env.example .env   # fill in DOMAIN, CERTBOT_EMAIL, POSTGRES_PASSWORD, JWT_SECRET; ENV=prod
./deploy/deploy.sh
```

Nginx serves the PWA on `/` and the API on `/api`; Postgres and the model container are internal only. The Docker files
have not been run yet in this repo's development environment (Docker was not installed); test on the VPS first.

## Data protection

This is a hackathon prototype on synthetic data. Before any real pilot, the **Nigeria Data Protection Act (NDPA) 2023**
compliance path is required: a Data Protection Impact Assessment (DPIA), an appointed Data Protection Officer (DPO),
lawful basis and consent flows reviewed by counsel, a retention and deletion policy, breach procedures, and data
processing agreements with any third party (LLM, SMS, hosting). External LLM calls are off unless
`ALLOW_EXTERNAL_LLM=true` and must only ever receive synthetic data.
